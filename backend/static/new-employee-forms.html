1. Scope and Success Criteria

Build a module that connects to theteam@jaccountancy.co.uk, finds emails with subject prefix New Employee Details:, extracts and validates submission data, matches employer to client/tenant, and publishes supported records to Xero Payroll.

Required completion sections

  • Personal details
  • Employment record
  • Base pay
  • Working pattern
  • Payment method
  • Tax setup
  • Student loan
  • Pension
  • Final verification

Overall status model

  • New
  • Extracted
  • Needs review
  • Ready to publish
  • Publishing
  • Partially published
  • Manual completion required
  • Complete
  • Failed
  • Archived

2. First Prerequisite: Prove Xero Payroll API Access

2.1 Inspect current app setup

  • Client ID, app type, redirect URLs
  • OAuth scopes and token storage
  • Refresh token rotation handling
  • Tenant selection mechanism
  • Payroll scopes currently authorised
  • UK Payroll partner permission availability

2.2 Add diagnostic endpoint

GET /api/admin/xero/payroll-diagnostic/:tenantId should call employees, pay run calendars, working patterns, and settings endpoints, then return capability flags.

{
  "tenantId": "uuid",
  "accountingApiConnected": true,
  "payrollApiConnected": true,
  "payrollSetupComplete": true,
  "payrollAdminAuthorised": true,
  "partnerPermissionAvailable": true,
  "errors": []
}

2.3 Proof-of-concept publication

In test org only: create employee, employment, salary/wages, payment method, then verify with GET calls before any live-client rollout.

3. Gmail Integration

Authentication

  • Use Google OAuth, never mailbox password automation
  • Default scope: https://www.googleapis.com/auth/gmail.readonly
  • Use gmail.modify only if labels are required

Search query

to:theteam@jaccountancy.co.uk subject:"New Employee Details:" has:attachment

Import strategy

  • Historic one-off import with pagination and dedupe by Gmail message ID
  • MVP polling every five minutes using last successful scan timestamp
  • Future push model with Gmail watch plus scheduled reconciliation

Idempotency

  • Unique constraint: gmail_message_id
  • Hash CSV and each attachment with SHA-256

4. Email and Attachment Processing

Subject parse rule

const prefix = "New Employee Details:";
const employeeName = subject.slice(prefix.length).trim();
  • Prefix match is case-insensitive
  • Name must not be empty
  • Store raw and parsed subject values
  • Flag form-name vs subject-name mismatches for review

Attachment selection priority

  • Exact filename entry-details.csv
  • Any CSV attachment
  • CSV with expected header signature
  • Email body fallback
  • PDF/image extraction as final fallback

Secure object storage

Store outside public web root using path pattern:

employee-submissions/{submissionId}/{attachmentId}/{sanitisedFilename}

5. CSV Parsing and Normalisation

Preserve raw values

{
  "fieldName": "National Insurance Number",
  "rawValue": "PL 29 60 01 B",
  "normalisedValue": "PL296001B"
}

Mapping layer

Implement versioned field map and retain unknown inputs in unmappedFields for monitoring.

Normalisation rules

  • UK date normalisation to ISO, reject ambiguous date values
  • NI shape validation, no identity ownership claims
  • Sort code: exactly six digits after stripping separators
  • Account number: numeric, max eight digits for electronic payment endpoint
  • Gender must map safely to Xero expectations, otherwise blocker
  • Name parser is reviewable and not auto-publish safe for complex names

6. Database Design

Create these tables with encrypted columns for sensitive fields where specified:

  • employee_submissions
  • employee_submission_data
  • employee_submission_attachments
  • xero_payroll_organisation_config
  • employee_publication_runs
  • employee_publication_steps
  • employee_manual_tasks

Attachment types: FORM_CSV, IDENTITY_DOCUMENT, P45, OTHER.

7. Employer and Xero Organisation Matching

Match hierarchy

  • Hidden client ID / hidden tenant ID (future form support)
  • Company number
  • Exact legal name / exact trading name / confirmed alias
  • Normalised and fuzzy matching only to suggest, never auto-publish alone

Thresholds

  • 100 percent exact mapped result: auto-match
  • 95+ percent single result: suggested
  • 80-94 percent: manual review required
  • Below 80 percent or tie: unmatched/manual selection

8. Organisation Payroll Configuration Sync

  • Pull payroll calendars and persist IDs, types, period/payment dates
  • Pull earnings rates and save default hourly/salary rate IDs per org
  • Pull working patterns and persist reusable pattern IDs
  • Track payroll readiness status: connected, setup incomplete, permission denied, token expired, reauth required, partner permission unavailable

9. Review Interface

Build review screen before live publication is enabled.

  • Header with employee, employer, received timestamp, source subject
  • Source panel: original email, CSV, ID attachment, raw values, parser version
  • Editable employee panel with masked sensitive fields by default
  • Employment panel for start date, employee number, calendar, NI category, contract metadata
  • Pay panel for hourly/salary details, earnings rate, working pattern, effective date
  • Payment panel for method and bank details
  • Tax and loans panel clearly marked manual-required where API is read-only
  • Validation panel with severity, field, explanation, resolution
Publish must remain disabled while blocker validations exist.

10. Duplicate Detection

Internal checks

  • Gmail message ID and CSV hash
  • Name plus DOB, NI number, existing run linkage

Xero checks

  • NI exact, email exact, name plus DOB, name plus start date, similar-name flags

Reviewer outcomes

  • Use existing employee
  • Create new employee (elevated permission + reason on strong warning)
  • Cancel submission
  • Mark duplicate

12. Step-by-Step Xero Publication

  • 12.1 Snapshot approved data and generate idempotency key
  • 12.2 Refresh token and validate tenant connection
  • 12.3 Confirm payroll access with employees read call
  • 12.4 Create employee and persist returned EmployeeID immediately
  • 12.5 Create employment with payroll calendar, start date, employee number, NI category
  • 12.6 Create salary-and-wages with tested field combinations
  • 12.7 Create employee working pattern where appropriate
  • 12.8 Create payment method with one electronic bank account
  • 12.9 Retrieve/verify employee, pay, payment, working pattern, and tax results
  • 12.10 Create manual tax task for starter declaration/student loan/postgrad loan
  • 12.11 Create manual pension review task
  • 12.12 Derive final per-section and overall status
Tax/student loan/pension may remain manual-required until completed in payroll operations.

13. Failure Handling and Retries

  • Never blindly restart from first step when partial success exists
  • Persist all external IDs to continue from correct step
  • Classify failures: auth, permission, payroll-config, validation, duplicate, rate-limit, transient, network, unknown
  • Auto-retry only transient classes (429/5xx/timeout) with backoff and cap
  • No auto-retry for validation/permission/auth failures
  • No automatic delete of partial employee records

14. Employee Number Strategy

  • MANUAL_ENTRY
  • NEXT_NUMERIC
  • PREFIXED_SEQUENCE
  • CLIENT_DEFINED

For automatic generation, use DB locking and Xero recheck before publish to avoid collisions.

15. Security and Data Protection

  • Encrypt sensitive DB columns and object storage
  • TLS everywhere and masked values in list views
  • Log sensitive-record access and enforce RBAC
  • Publisher-only publication rights with approval controls
  • No sensitive values in app logs/monitoring payloads
  • Retention and deletion policy enforcement
  • Short-lived signed URLs for attachments
  • Secure backups to same standard as primary systems

Suggested roles: PAYROLL_VIEWER, PAYROLL_PROCESSOR, PAYROLL_PUBLISHER, PAYROLL_ADMIN, SYSTEM_ADMIN.

16. Audit Trail

Record all actions end-to-end, including imports, parsing, value edits, matching decisions, publication requests/responses, manual task lifecycle, and archival actions.

  • Email imported
  • CSV parsed
  • Normalisation and overrides
  • Organisation match and override events
  • Employee number assignment
  • Approval and publish events
  • Xero request and response checkpoints
  • Manual completion task events
Audit text must never include unmasked NI or bank details.
