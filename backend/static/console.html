Help

How Jenius AI works from first sync through daily chasing.

What this console does

The console connects to Xero, imports sales invoices and contacts, then organises them into a credit-control ledger. It groups invoices by client, shows outstanding balances, highlights overdue accounts, tracks local credit-control notes, and lets you push notes back into Xero so the account history is visible outside this tool too.

Where things are

The left sidebar holds Home, Clients, Invoices, LPCs, Settings, Xero login/resync, and Back to Jenius. The top of the ledger shows totals and status chips. The table controls hold search, sorting, filtering, columns, dense view, reset filters, and CSV export. Opening a client shows the invoices, notes, generated letters, payment plans, files, status history, and audit trail for that client.

First sync

  1. Open Settings from the left sidebar.
  2. Choose the invoice years you want to import. No years are selected by default so you stay in control of the data volume.
  3. Choose the data filter. Outstanding invoices only is fastest. Full invoice history imports the biggest dataset.
  4. Run import. The first sync has to build the local ledger from scratch, so it can take longer while contacts, outstanding invoices, and any selected paid invoice history are pulled from Xero.

Resyncs after the first import

Later syncs are designed to be quicker. Once the selected years already exist locally, the backend asks Xero for records changed since the last successful sync, with a small overlap window so changes made during the previous sync are not missed. It still performs a fuller fetch if you add a new invoice year or expand the history scope, because those older invoices may not exist locally yet.

The resync also fetches changed sales invoices broadly enough to catch status changes, for example an invoice moving from outstanding to paid, then recalculates client totals so the ledger stays current.

Behind the scenes

This screen is the embedded web console. It talks to the backend API, which stores the local ledger, sync settings, notes, audit entries, and Xero connection details. Xero remains the source for invoice and contact data, while the console adds the credit-control workflow on top: statuses, notes, letter generation, filters, and sync logs.

Ledger and client screens

The main ledger is the working list. Use the status chips, search, sort, filter, columns, dense table, export, and row actions to find invoices and open a client. Selecting a row opens the client screen, where you can review contact details, open invoices, interest guidance, invoice notes, client notes, status history, payment plans, attachments, and audit activity.

Late payment charge review

The dashboard card and table options menu open the late payment charge queue. It lists invoices more than 14 days overdue, shows which ones are ready, already charged, or blocked by missing Xero contact data, and raises the selected charges back into Xero after review.

Letter templates and generated letters

Open Settings from the left sidebar to create and edit letter templates. Templates can use fields such as {{client_name}}, {{contact_name}}, {{total_due}}, {{invoice_list}}, {{today}}, and selected invoice fields. On the client screen, choose a template in the Letters section and generate it. The generated letter is shown for review, can be copied, and is automatically saved as a client note.

Xero note write-back

When you add notes, change invoice status, create payment plans, write off debt, or raise late payment charges, the console first saves the local audit trail. It then uses the connected Xero account to add history notes to the matching Xero contact and invoice where available. If Xero is disconnected or rejects a note, the local update remains and the app shows an error so you can reconnect or retry.

Settings, logs, and troubleshooting

Settings controls invoice import scope, import years, letter templates, Xero disconnect, and developer logs. Developer log shows recent sync runs and backend/Xero errors, which is useful if a sync fails or Xero returns a permission, rate limit, or authentication message. If Xero is disconnected, use the sidebar login button before syncing again.

Leaving the console

Use Back to Jenius at the bottom of the left sidebar to return to the main Jenius site. Log Out is handled by the surrounding Jenius navigation outside this embedded console. Closing this Help panel returns you to the same screen you were using.
